01 Key concepts to understand
The Boundary

Training Cutoff

Every AI is trained on data up to a certain date — after that it knows nothing new. DeepSeek-R1's cutoff is ~July 2024. Events very close to that date have sparse training data, so the model's memory is shakier there.

The Experiment

Thinking ON vs Thinking OFF

ON — model reasons step by step before answering, like showing its work. OFF — model answers directly with no reasoning. We compare both to see which gets more overconfident near the cutoff.

The Metric

Overconfidence Gap

Gap = stated confidence − actual accuracy × 100. If the model says "90% sure" but is only right 40% of the time, the gap is +50. Positive = overconfident. Zero = perfect. Negative = underconfident.

Critical distinction

Inference, not Training

We are not training any model. Training costs millions of dollars and months of compute. We are only asking questions to an already-trained model and measuring its answers — like giving someone a quiz, not teaching them.

Model Size

What "14B" means

14 Billion parameters — the number of values inside the model that determine how it thinks. Bigger = smarter but more expensive. We used 14B for the pilot. Phase 2 will use the full 671B model via API.

Why DeepSeek first

Strategy behind the choice

Open source (free to download and run), native Thinking ON/OFF switch, known training cutoff. Claude and GPT-4o come in Phase 3 — cross-model comparison makes the paper stronger. Start cheap, prove the idea, then scale.

⚠
Honest problems with the current version
Things a reviewer would reject this for right now
1
The result contradicts the hypothesis
We expected overconfidence. We found underconfidence. The model said "5% sure" while being 50% accurate. That's still a finding — but it complicates the story. A stronger model in Phase 2 might show the overconfidence we expected. Or it might not. We don't know yet.
2
Self-reported confidence is weak methodology
We asked the model to say "I'm 80% sure." Reviewers at serious venues know these numbers are unreliable — the model is guessing a number, not giving a real probability. The correct method is token log-probabilities — the actual maths of what the model thinks. Already planned but not built yet.
3
N=50 is too small to claim anything
10 questions per bucket is not enough for statistical significance. If one question goes wrong by luck, it changes the entire bucket's result. Need at least 100 per bucket (500 total) to say anything meaningful.
4
Only one model family
Results from one model = one data point. Reviewers will ask: "Is this specific to DeepSeek, or does it hold generally?" You can't answer that without testing Claude and GPT-4o too.
5
The Thinking OFF method is a workaround
We force the model to skip reasoning by pre-filling empty think tags. This is a hack — the model is RL-trained to always reason, so this condition is unnatural. A cleaner baseline would be a different model that doesn't reason at all.
🛠
What to change to make the paper stronger
Concrete fixes, in order of importance
Must do
Switch to log-probability confidence
Instead of asking "how confident are you?", use the model's internal token probabilities — the actual mathematical output. This is already stubbed in src/api_runner.py. Implementing this turns a weak methodology into a strong one. No extra API cost.
Must do
Scale to 500+ questions (100 per bucket)
100 per bucket gives enough statistical power to run proper significance tests. Write questions semi-automatically using ChatGPT or Gemini as a draft generator, then manually verify each one. This is Phase 2 of the plan.
Must do
Test at least 3 model families
DeepSeek-R1 (done), Claude 3.7 Sonnet (has extended thinking), GPT-4o (with/without chain-of-thought prompting). A finding that appears in all three is publishable. One that appears in only DeepSeek is a curiosity.
Should do
Add a clean non-reasoning baseline
Use a plain instruct model (like Llama-3-Instruct, which has no reasoning mode at all) as the OFF baseline instead of the hack. This makes the ON vs OFF comparison scientifically clean.
Should do
Add statistical significance tests
Bootstrap confidence intervals on the overconfidence gap. Without these, a reviewer can dismiss the whole thing as noise. Python's scipy.stats handles this in 10 lines of code — already have the data structure for it.
Nice to have
Add more temporal buckets
Currently 5 buckets (1, 3, 6, 12, 24 months). Adding 2-week and 2-month buckets near the cutoff would give a much finer picture of exactly where the calibration breaks down.

Bottom line

The idea is worth pursuing. The research gap is real — no paper combines CoT reasoning, temporal proximity to training cutoff, and calibration in one study. Two papers already show CoT causes overconfidence generally, which means the field is interested in this direction. Your angle — does it get worse near the knowledge boundary? — is the specific new contribution.

But go into the supervisor meeting knowing this is a pilot, not a finished paper. The pitch is: "I found a real gap, proved the pipeline works, and need resources to scale it up." That is an honest and strong pitch. Don't oversell the current result.
